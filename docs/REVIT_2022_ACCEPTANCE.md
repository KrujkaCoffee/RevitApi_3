# Проверка клиента в Revit 2022

## Сборка

```powershell
dotnet build .\RevitApi_3.sln -c Release -p:RevitInstallDir="C:\Program Files\Autodesk\Revit 2022"
```

Для тестового API перед запуском Revit можно задать:

```powershell
$env:REVIT_ERP_BASE_URL = "http://test-server:20011"
```

## Приёмочный сценарий

Тестовый файл: `ТХ Упаковочные системы LDPE31.08.26_отсоединено.rvt`.

1. Открыть `О_Спецификация сводная` и выполнить «Таблица сопоставления кодов 1C (по выбранной спецификации)».
2. Сверить порядок, многоуровневые названия и текст ячеек каждой колонки с открытой спецификацией. Для колонок с нижними заголовками `1`, `2`, `3`, `4` над номером должно отображаться содержательное название. Скрытые поля в таблицу плагина попадать не должны; формулы и итоги должны совпасть как строки.
3. Проверить колонку «Связь с Revit»: строки номенклатуры должны содержать число связанных элементов, а заголовки/итоги — явное служебное пояснение. Строки с `ADSK_Марка`, `ADSK_Завод-изготовитель` и типовыми `ADSK_Наименование`/`ADSK_Код изделия` должны связываться так же, как строки без этих полей; предупреждений о массовом отсутствии точного совпадения быть не должно.
4. Проверить фильтр слева по значению любой видимой ячейки, коду ERP, названию ERP и тексту диагностики связи.
5. Выбрать две трубы одного семейства, но разных типоразмеров (например, 108×3 и 133×3), назначить разные коды и сохранить. После повторного открытия убедиться, что коды остались разными.
6. Если одинаковая номенклатура повторяется в разных системах/группах, назначить код одной строке. Код должен примениться ко всем визуально неразличимым строкам и одному объединённому набору элементов.
7. Проверить миграцию старой типовой привязки: существующее значение переносится экземплярам, а `ADSK_Код изделия` не изменяется.
8. Включить «Глобальный поиск»: дерево должно заблокироваться, запрос должен начаться после двух символов, окно должно оставаться отзывчивым. После снятия галки результат очищается, дерево снова доступно.
9. Открыть выгрузку активной спецификации. Превью должно содержать те же видимые колонки, многоуровневые заголовки и все строки `Body` в том же порядке. Серым показаны заголовки/итоги, красным — строки ресурсов без кода ERP.
10. Изменить только «Количество», выполнить проверку и убедиться, что ошибка API переводит к исходной строке Revit.
11. Выполнить экспорт. Закрыть и снова открыть окно: название ресурсной и ссылка `e1c://` должны сохраниться на активной спецификации, автор ссылки должен совпадать с полем «Автор».

При открытии окна клиент временно включает itemized-режим и подставляет служебные маркеры в `Код 1C-ERP`, чтобы Revit сам вернул отображаемые значения каждого экземпляра через `GetCellText`. Эта транзакция всегда откатывается до показа окна. До назначения нового кода и после закрытия через «Отмена» исходная группировка спецификации и все ERP-коды должны оставаться без изменений.

Критический инвариант: назначение кода допускается только для строки, связанной с точным набором `ElementId`. Несколько визуально неразличимых строк считаются одной номенклатурной группой и получают один код; при недостатке признаков клиент блокирует запись вместо изменения типа или семейства целиком.
