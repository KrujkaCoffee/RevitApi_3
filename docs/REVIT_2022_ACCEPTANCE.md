# Проверка клиента в Revit 2022

## Сборка

```powershell
dotnet build .\RevitApi_3.sln -c Release -p:RevitInstallDir="C:\Program Files\Autodesk\Revit 2022"
```

Для тестового API перед запуском Revit можно задать:

```powershell
$env:REVIT_ERP_BASE_URL = "http://test-server:20011"
```

## Приёмочный сценарий

Тестовый файл: `ТХ Упаковочные системы LDPE31.08.26_отсоединено.rvt`.

1. Открыть `О_Спецификация сводная` и выполнить «Таблица сопоставления кодов 1C (по выбранной спецификации)».
2. Сверить порядок, названия и текст ячеек каждой колонки с открытой спецификацией. Скрытые поля в таблицу плагина попадать не должны; формулы и итоги должны совпасть как строки.
3. Проверить фильтр слева по значению любой видимой ячейки, коду ERP и названию ERP.
4. Выбрать две трубы одного семейства, но разных типоразмеров (например, 108×3 и 133×3), назначить разные коды и сохранить. После повторного открытия убедиться, что коды остались разными.
5. Проверить миграцию старой типовой привязки: существующее значение переносится экземплярам, а `ADSK_Код изделия` не изменяется.
6. Включить «Глобальный поиск»: дерево должно заблокироваться, запрос должен начаться после двух символов, окно должно оставаться отзывчивым. После снятия галки результат очищается, дерево снова доступно.
7. Открыть выгрузку активной спецификации. Превью должно содержать те же видимые колонки и все строки `Body` в том же порядке. Серым показаны заголовки/итоги, красным — строки ресурсов без кода ERP.
8. Изменить только «Количество», выполнить проверку и убедиться, что ошибка API переводит к исходной строке Revit.
9. Выполнить экспорт. Закрыть и снова открыть окно: название ресурсной и ссылка `e1c://` должны сохраниться на активной спецификации, автор ссылки должен совпадать с полем «Автор».

Критический инвариант: назначение кода допускается только для строки, однозначно связанной с `ElementId`. При неоднозначности клиент блокирует запись вместо изменения типа или семейства целиком.
